# 3. Архитектура учебного материала

Конспект строится из трёх взаимосвязанных уровней.

## 3.1. Уровень 1 — определение и основные понятия

Каждую новую тему или самостоятельное понятие начинай с точного определения.

Определение должно:
- Объяснять суть механизма.
- Использовать корректную терминологию.
- Быть понятным без дополнительных вступлений.
- Не содержать технически неверных упрощений.

Например:

**Вычисляемое свойство** — это свойство, значение которого вычисляется на основе других данных объекта при обращении к нему, а не хранится как независимое состояние.

Определение должно быть достаточно ёмким, чтобы при повторении по нему можно было быстро восстановить суть механизма.

Не начинай каждую небольшую операцию с нового определения. Если она является продолжением уже изученного понятия, достаточно короткого объяснения.

## 3.2. Уровень 2 — раскрытие механизма

После определения раскрывай тему через небольшие смысловые подразделы.

Каждый подраздел должен объяснять одну конкретную особенность, операцию или проблему.

Например, при изучении атрибутов класса:

- Обращение к атрибуту.
- Проверка наличия атрибута.
- Создание атрибута.
- Изменение атрибута.
- Удаление атрибута.

При изучении свойств:

- Получение значения свойства.
- Изменение значения.
- Удаление свойства.
- Вычисление значения.
- Кэширование результата.

Не объединяй разные механизмы в один большой раздел, если между ними есть существенные различия.

## 3.3. Уровень 3 — объединение изученного

После изучения нескольких взаимосвязанных понятий при необходимости добавляй объединяющий пример.

Его задача — показать, как изученные механизмы работают вместе в одном классе.

Например, после изучения:
- Атрибутов класса.

Объединяющий пример не должен повторять всю теорию. Он демонстрирует взаимодействие изученных элементов.

Добавляй его только тогда, когда он действительно улучшает понимание.

# 4. Логика изложения

Основной принцип построения последовательности:

**Исходная ситуация → проблема → причина проблемы → решение → новый механизм → его особенности и ограничения → улучшение решения.**

Используй только необходимые этапы.

Не создавай искусственные проблемы ради соблюдения шаблона.

## 4.1. Объяснение причин

Не ограничивайся сообщением о том, что делает механизм.

Показывай:
- Зачем он нужен.
- Какую проблему решает.
- Почему предыдущего способа недостаточно.
- Что изменяется после его применения.
- Какие новые возможности появляются.
- Какие ограничения остаются.

Например, при объяснении `@property`:

1. Хранение зависимого атрибута создаёт риск рассинхронизации.
2. Вычисление свойства устраняет эту проблему.
3. Но вычисление происходит при каждом обращении.
4. Кэширование уменьшает количество вычислений.
5. Кэш может устареть после изменения исходных данных.
6. Сброс кэша при изменении исходных данных решает проблему актуальности.

Именно такая последовательность раскрывает не только синтаксис, но и назначение механизма.

## 4.2. Не перегружай последовательность

Не обязательно раскрывать каждую тему через проблемы и решения.

Если механизм достаточно прост, сразу объясняй его назначение и показывай применение.

Не добавляй искусственные промежуточные этапы, если они не помогают понять материал.

# 9. Объединяющие и итоговые примеры

После изучения группы взаимосвязанных механизмов можно добавить раздел:

**Объединяем изученное**

В нём используй один полноценный пример, который демонстрирует совместную работу ранее рассмотренных элементов.

Например:

```python
from math import sqrt


class Point:
    list_points = []

    def __init__(self, x=0, y=0):
        self.move_to(x, y)
        Point.list_points.append(self)

    def move_to(self, new_x, new_y):
        self.x = new_x
        self.y = new_y

    def go_home(self):
        self.move_to(0, 0)

    def calc_distance(self, another_point):
        if not isinstance(another_point, Point):
            raise ValueError("Аргумент должен принадлежать классу Point")

        return sqrt(
            (self.x - another_point.x) ** 2
            + (self.y - another_point.y) ** 2
        )


p1 = Point(6, 0)
p2 = Point(0, 8)

print(p1.calc_distance(p2))  # 10.0
```

Объясняй только те взаимодействия, которые важны для текущей темы.

Не вводи в объединяющий пример большое количество новых механизмов, которые ещё не изучались.

Не создавай итоговый пример ради формального завершения каждого раздела.

Публичные курсы могут быть доступны анонимно.

Для записанных и платных курсов используй:

`Authorization: Bearer $STEPIK_TOKEN`

Токен хранится в `.env`.

Пользователь самостоятельно обновляет токен.

Срок действия используемого токена составляет приблизительно 10 часов.

При HTTP 401:
1. Прекрати повторные запросы с тем же токеном.
2. Сообщи пользователю, что необходимо обновить `STEPIK_TOKEN` в `.env`.
3. Продолжай работу после обновления.

**Не создавай и не восстанавливай `stepik_auth.py`.**

Не реализуй автоматическое получение токена без отдельного явного запроса.

Не выводи токены в сообщения, логи или конспекты.

## 12.2. Получение материалов

Используй цепочку:

1. `GET /courses/{course_id}`
2. Получение `sections`.
3. `GET /sections/{section_id}`
4. Получение `units`.
5. `GET /units/{unit_id}`
6. Получение `lesson`.
7. `GET /lessons/{lesson_id}`
8. Получение `steps`.
9. `GET /steps/{step_id}`

Для получения нескольких шагов используй пакетный запрос:

`GET /steps?ids[]=1&ids[]=2`

Проверяй фактическую структуру ответов API.

Не предполагай наличие полей, которые не были получены.

## 12.3. Типы содержимого

Основной тип лекционного блока:

`block.name == "text"`

HTML-содержимое:

`block.text`

При преобразовании HTML сохраняй:
- Заголовки.
- Абзацы.
- Списки.
- Выделения.
- Код.
- Формулы.
- Логическую последовательность.

Учитывай типы заданий:
- `choice`
- `code`
- `string`
- `math`

Не смешивай условия задач с основным текстом лекции.

Включай задачи в конспект только тогда, когда они помогают раскрыть изучаемый механизм.

Если материал недоступен или неполон, сообщи об этом. Не восстанавливай отсутствующее содержание выдуманными сведениями.

# 13. Работа с Notion API

## 13.1. Источник истины

**Notion — основной источник истины для конспектов.**

Локальные Markdown-файлы являются производными экспортами из Notion.

Перед изменением локального файла обязательно уточняй у пользователя, не будет ли его изменение перезаписано последующим экспортом.

Не выполняй автоматическую синхронизацию.

## 13.2. Права доступа

По умолчанию:

- Чтение разрешено.
- Анализ материалов разрешён.
- Подготовка конспекта разрешена.
- Запись в Notion — только по явному запросу.
- Изменение существующих блоков — только по явному запросу.
- Изменение локальных файлов — только по явному запросу.
- Git-операции — только по явному запросу.

Не удаляй и не перезаписывай существующие данные без разрешения.

## 13.3. Подключение

Заголовки:

```http
Authorization: Bearer $NOTION_TOKEN
Notion-Version: 2022-06-28
Content-Type: application/json
```

Токен хранится в `.env`.

Не раскрывай секреты.

Предпочитай доступные подключённые Notion-инструменты, если они позволяют выполнить требуемую операцию.

Не утверждай, что запись выполнена, пока API не подтвердил операцию.

## 13.4. Целевая страница

Основная страница:

**Название:** Шпаргалка: Объектно-ориентированное программирование на Python

**Page ID:**

`296c66da-696a-805e-8cad-e4c53623d785`

**URL:**

https://app.notion.com/p/arkady-kolosov/Python-296c66da696a805e8cade4c53623d785

Не создавай новую страницу вместо неё без отдельного указания пользователя.

## 13.5. Чтение страницы

Используй:

```http
GET /v1/blocks/{page_id}/children?page_size=100
```

Обрабатывай пагинацию через `start_cursor`.

Если `has_more == true`, продолжай получение блоков.

При анализе учитывай:
- `heading_1`
- `heading_2`
- `heading_3`
- `paragraph`
- `code`

Не ограничивайся первыми 100 блоками.

## 13.6. Иерархия заголовков

Соблюдай структуру:

- `heading_1` — название самостоятельной темы.
- `heading_2` — крупные смысловые разделы.
- `heading_3` — подразделы внутри крупного раздела.
- `paragraph` — определения и объяснения.
- `code` — примеры кода.

Не создавай избыточное количество заголовков.

Если мысль можно раскрыть одним абзацем, не создавай отдельный подраздел.

Сохраняй логическую иерархию темы.

## 13.7. Размещение конспекта

Перед публикацией:
1. Получи актуальную структуру страницы.
2. Найди целевой тематический заголовок.
3. Определи границы его раздела.
4. Проверь наличие существующего содержимого.
5. Найди правильное место вставки.

Для вставки используй:

```http
PATCH /v1/blocks/{page_id}/children
```

Структура:

```json
{
  "children": [],
  "after": "BLOCK_ID"
}
```

`after` указывает блок, после которого вставляются новые блоки.

Для известного раздела «Пространство имен класса и экземпляра» содержимое должно располагаться после его заголовка и перед следующим разделом «Инкапсуляция».

Для новых тем соблюдай аналогичное правило.

Если заголовок темы отсутствует, согласуй создание нового раздела и его расположение с существующей структурой.

Не перемещай соседние разделы.

## 13.8. Преобразование конспекта в Notion blocks

Используй:

| Элемент | Notion block |
|---|---|
| Название темы | `heading_1` |
| Основной раздел | `heading_2` |
| Подраздел | `heading_3` |
| Определение | `paragraph` |
| Объяснение | `paragraph` |
| Python-пример | `code` |

Для кода используй язык `python`.

Пример:

```json
{
  "object": "block",
  "type": "code",
  "code": {
    "rich_text": [
      {
        "type": "text",
        "text": {
          "content": "print('Hello')"
        }
      }
    ],
    "language": "python"
  }
}
```

Для текста используй `rich_text`.

Поддерживай inline-аннотации:
- `bold`
- `code`

Не объединяй весь конспект в один большой paragraph или code block.

Каждый смысловой блок должен сохранять свою структуру.

Учитывай ограничения Notion API на размер rich_text и количество блоков в одном запросе. При необходимости разбивай публикацию на несколько запросов, сохраняя порядок.

## 13.9. Защита от дублирования

Перед записью проверь:
- Существует ли заголовок темы.
- Содержит ли раздел уже конспект.
- Не публиковался ли материал ранее.
- Не повторяются ли существующие блоки.

Если раздел пустой — заполняй его.

Если раздел уже содержит материал:
- Не добавляй дубликат.
- Не перезаписывай существующие блоки автоматически.
- Сообщи пользователю о найденном содержимом.
- Уточни, требуется ли обновление, дополнение или замена.

## 13.10. Проверка публикации

После записи:
1. Проверь результат через API.
2. Убедись, что все блоки добавлены.
3. Проверь порядок заголовков.
4. Проверь содержание примеров.
5. Убедись, что код имеет язык `python`.
6. Проверь, что соседние разделы не повреждены.

Не сообщай об успешной публикации, если результат не удалось проверить.

# 15. Обработка ошибок

### Stepik

При HTTP 401 сообщи о необходимости обновить `STEPIK_TOKEN` в `.env`.

Не создавай механизм автоматического получения токена.

### Notion

При HTTP 401 или 403:
- Проверь наличие подключения.
- Сообщи о необходимости проверить `NOTION_TOKEN` и права интеграции.
- Не раскрывай секреты.

При ошибке записи:
- Не считай операцию успешной.
- Не повторяй вставку вслепую.
- Сначала проверь актуальное состояние страницы.

### Неполные материалы

Если часть лекции недоступна:
- Не выдумывай содержание.
- Укажи, какие данные отсутствуют.
- Используй только подтверждённую информацию.

### Изменение существующих данных

Перед удалением, заменой или перемещением существующих материалов получи явное разрешение пользователя.
