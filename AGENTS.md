# AGENTS.md

## Project

Конспект по Python: шпаргалки по темам в `notes/`, примеры кода в `base_summary.py` и `func_summary.py`, план тем в `roadmap.py`, шаблон конспекта — `notes.txt`.

## Права доступа

- По умолчанию разрешено только чтение: читать файлы, искать по содержимому, смотреть структуру.
- Создавать, изменять, удалять и перемещать файлы — только по явному запросу пользователя.
- Операции git (включая `git status` и `git diff`) — только по явному запросу.
- Результат работы по конспекту по умолчанию — текст в чате; заметки и Notion не изменяются.

## Conventions

- Read the relevant modules before making changes
- Keep consistent with the existing code style

## Работа с конспектом

- Пользователь присылает тему, материал лекции и свой код — результат: готовый фрагмент конспекта, который можно перенести в заметки без правок.
- **Без явного запроса не изменять заметки, Notion и файлы репозитория.** По умолчанию результат — текст в чате.
- Язык — русский. Стиль строгий, лаконичный, технически точный и понятный новичку: без воды, повторов, очевидных объяснений, искусственных аналогий и фраз вроде «Давайте разберёмся».

### Структура фрагмента

Тема → ёмкое определение (что это, принцип работы, для чего) → короткие смысловые разделы → постепенно развивающиеся примеры → итоговая реализация, если нужна.

- Каждый следующий раздел отвечает на вопрос, который возникает после предыдущего: исходная ситуация → проблема → причина → решение → новый механизм → ограничения → улучшение. Использовать только этапы, нужные теме.
- Объяснение — перед кодом; после кода — только новая важная деталь.
- Подзаголовки короткие и содержательные.
- Не добавлять оценку конспекта, рекомендации по оформлению и заключительные фразы вне учебного материала.

### Примеры кода

- Развивать один основной класс: каждая версия продолжает предыдущую, меняется только то, что относится к текущему этапу.
- Примеры зеркальные: те же имена, структура, данные и действия с экземпляром. Новую версию класса приводить полностью, с созданием экземпляра.
- Использовать исходные примеры и код пользователя, не придумывать другие классы без необходимости.
- Все примеры рабочие, кроме намеренно показанных ошибок. Комментарии с результатами (`print(sq.area)  # 100`) соответствуют реальному поведению Python.
- Объяснять поведение кода, а не пересказывать строки; не комментировать очевидное.

### Точность

- Исправлять технические неточности лекции, кратко указывать на ошибки в исходном коде, если они влияют на выполнение.
- Не вводить новые сложные механизмы, не нужные для понимания текущей темы.

### Правила работы

- **Линтер**: всегда следовать правилам `ruff check .` перед завершением задачи; при конфликте автоформатирования — применить `ruff format .`. Запуск `ruff check .` не требует запроса разрешения у пользователя — это обязательная автоматическая проверка.
- **Коммиты**: GigaCode предлагает commit message на английском в формате Conventional Commits: `<type>: <subject>` (типы: `feat`, `fix`, `chore`, `refactor`, `test`, `docs`, `style`), анализируя текущие изменения. Коммиты выполняются только по явной просьбе пользователя.
- **Чтение файлов**: инструменты `read_file`, `grep_search`, `glob` и аналогичные не требуют запроса разрешения. Разрешение нужно только на изменение (`edit`, `write_file`, `delete`).
- **Временные файлы**: удалять через `rm -f`, не через `del`. Не создавать файлы с именем `nul`.
- **notes.txt**: файл игнорируется, не используется в работе.
